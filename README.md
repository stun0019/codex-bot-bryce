# Codex Bot Bryce — Binance 策略掃描

頁面在原本「全部訊號」的位置提供「策略掃描」。舊市場雷達、五因子評分引擎、設定與測試已移除。新版策略掃描使用 `strategy-engine.js`、`strategy-data.js` 與 `strategy-scanner.js`；模擬交易另外載入 `price-feed.js`、`paper-engine.js` 與 `paper-panel.js`。不會啟動舊訂單流程或寫入後端訂單。

## 本版策略

僅使用幣安已收盤的 **4H 與 15M** K 線，不抓取或混用其他週期。MA 為收盤價的簡單移動平均（SMA），不是 EMA。

| 判定 | 做多 | 做空 |
| --- | --- | --- |
| 4H 方向 | 收盤價 > MA20，且本根 MA20 > 前一根 MA20 | 收盤價 < MA20，且本根 MA20 < 前一根 MA20 |
| 15M 回踩／反彈 | 確認 K 或緊鄰前一根 K 的高低區間觸及該根 MA10 或 MA20 | 相同觸及條件 |
| 15M 收盤確認 | 前一根收盤 ≤ 當時 MA5，確認 K 收盤 > 當時 MA5 | 前一根收盤 ≥ 當時 MA5，確認 K 收盤 < 當時 MA5 |

條件必須全部成立才顯示候選。依使用者最新指示，本版暫不使用 HH／HL、LH／LL 結構或成交量條件；不以舊雷達分數排序。候選依合約名稱排列。

## 資金與風險

- 初始總資金：**70 USDT**，可在頁面調整並儲存在瀏覽器本機。
- 單筆風險預算：總資金 × **3%**，70 USDT 對應 **2.10 USDT**。
- 進場參考：15M 確認 K 收盤價。
- 停損：若前一根 K 觸及 MA10／20，使用該根與確認 K 的區間極值；只有確認 K 觸及時則使用確認 K 極值。做多放在最低點下方 1 tick，做空放在最高點上方 1 tick。
- 目標：依進場至停損的距離計算 **至少 2R**，並朝有利方向對齊 tick 精度。
- 部位數量：風險預算 ÷ 停損距離，再依幣安 LOT_SIZE 向下取整並遵守最大數量。估算價格風險不超過預算；部位不足最小數量或名目金額時顯示原因。

3% 指單筆的資金風險，不是固定停損價差。風險／獲利是價格差估算，未含手續費、滑價與資金費率，也不保證實際成交損失上限。名目部位可能高於總資金，保證金需求依實際槓桿而定。多筆候選各自計算 3%，沒有執行交易或自動分配多筆保證金。

## 資料、更新與畫面

- 透過 `https://fapi.binance.com/fapi/v1/exchangeInfo` 篩選交易中的 USDT 永續合約；每輪重新讀取 `/fapi/v1/ticker/24hr`，依官方 `quoteVolume`（24 小時 USDT 成交額）由高到低選取前 20 個，只有這些合約會進入策略掃描。有效資料少於 20 個時只掃描實際可用數量；排名資料失敗時回報錯誤，不改掃全市場。
- 使用 `/fapi/v1/time` 與 `/fapi/v1/klines` 對齊幣安時間。只允許 `4h`、`15m`，每次讀取 80 根。
- 先檢查 4H 趨勢，成立後才抓該合約 15M。前 20 名合約初次掃描需要一段時間，畫面顯示即時進度與已符合條件的候選。
- 全域請求間隔 250ms、最多 3 個工作並行；遇到 429／418 依 Retry-After 暫停；單一合約資料錯誤會跳過並顯示計數。
- 各週期資料快取至該週期下一個收盤邊界。每根 15M 收盤後自動重新掃描；舊候選到期即移除，且排除未收盤、缺漏、重複或過期 K 線。
- 卡片顯示多空方向、進場參考、停損、目標、估算風險、目標獲利與部位數量；可展開查看均線及確認時間。
- 掃描使用幣安原生合約名稱與單位，例如 `1000PEPEUSDT` 保留千顆合約單位，數量、tick 與停損風險使用同一單位。

## 使用

將 `site/` 作為靜態網站根目錄，或透過儲存庫根目錄 `index.html` 導向 `site/`。新版掃描頁不需要 `/api/orders` 後端或 API Key。舊版訂單／推播的資產保留在儲存庫，但掃描頁不會載入它們。公開價格模組會供模擬交易追蹤使用。

策略卡片仍是待執行候選，並由下方獨立的前向模擬面板累積結果。**不會真實自動下單；歷史回測由下方獨立面板執行**；上方總資金不會因模擬盈虧自行變動。

## 前向模擬交易（第一版）

策略掃描下方新增「模擬交易」。此功能從啟用後開始累積結果，不是歷史 K 線回測，也不會向幣安送出真實交易。

- 新候選以 `幣種＋方向＋15M 確認時間` 去重，同一訊號只記錄一次；候選依照其產生後的新成交報價模擬進場，沒有回填已過去的確認 K 收盤價。
- 沿用訊號的停損、止盈；按模擬進場價檢查價差盈虧比至少 1:2。若報價已越過界線、盈虧比不足、30 秒內沒有新報價、或數量未達幣安最小要求，就記錄「略過」與原因。
- 70 USDT 為預設單筆參考總資金，每筆風險預算 3%；數量依新成交價重算，將估算進出場手續費與停損滑價納入預算。因此部位可能與策略卡片的未含費用參考數量不同。
- 預設單邊手續費 0.05%、單邊不利滑價 0.02%，都是可調整的模擬假設，不代表實際帳戶費率。每筆訊號會固定當時資金、費率與滑價，調整只影響後續新紀錄。
- 透過公開行情 WebSocket 接收成交報價，逐次檢查停損／止盈觸價；模擬市價出場使用觸發時報價加不利滑價。行情跳價可能導致損失超過原先預算，費後盈虧比也可能低於 2R。未計資金費率與委託簿深度。
- 已進場的紀錄不因候選到期或下一輪不再符合策略而消失；「暫停新增」仍會繼續追蹤原有持倉。
- 每筆訊號獨立模擬，可以同時記錄不同訊號；沒有共用保證金、槓桿限制或帳戶淨值資金曲線。累計盈虧與回撤都是獨立訊號結果的合計。
- 勝率以淨損益大於 0 的已平倉筆數，除以所有已平倉筆數。未平倉、略過與待核對不列入分母。另顯示多空勝率、平均淨損益、最大連敗與累積淨損益回撤。
- 新版聚合成交持倉在重新開啟頁面、斷線、成交編號缺漏或超過 30 秒未取得報價後，先轉為「核對中」。完成缺失成交的核對後恢復追蹤或補記出場；無法證明完整性才保留待核對。舊版未保存成交編號的紀錄保留，不回填結果。
- 紀錄保存在目前網站／瀏覽器的 localStorage，支援 JSON 匯出。清除網站資料、更換瀏覽器或更換網址不會自動沿用紀錄。
- 使用 Web Locks 確保同一網站同時只有一個分頁負責追蹤，其他分頁唯讀。需使用支援 Web Locks 的 HTTPS 或 localhost 環境。

第一版需要保持頁面與網路可用。若要在關閉瀏覽器後繼續追蹤，需再增加常駐後端與資料庫。

## 刷新與斷線後自動核對

此升級仍只使用本裝置瀏覽器保存紀錄，不需要後端、API Key 或真實下單權限。頁面關閉期間沒有程式執行；重新開啟才補查已存在的持倉，不補開離線期間的新訊號。

- 新持倉只接受原生合約單位的 aggTrade 行情，保存 Binance 聚合成交編號、成交時間 T、價格與完整持倉／TP 狀態。Ticker 不作為持倉成交依據。每次保存將狀態與檢查點一起寫入原 localStorage 紀錄；重大進出場與 TP 事件立即保存，一般報價最多每 5 秒保存，意外中止後可從最後成功保存的檢查點重播。
- 刷新、頁面離開、斷線或成交序列中斷後保留原進場、數量、停損、目標與費率，先排入核對。核對中不接受單一最新價直接恢復，也不回填等待成交的訊號。
- 使用 GET /fapi/v1/aggTrades，先固定本批最新成交作為銜接點，再從最後保存編號含首筆分頁查詢。核對原始檢查點、編號連續、成交時間順序及最後銜接點，才按相同交易引擎重播。每頁最多 1000 筆、請求間隔 750ms，每批最多 20 頁；較長中斷分批保存已驗證進度並繼續。
- 補查時即時行情以成交編號暫存，歷史補齊後去重合併。若緩衝缺漏或連線再度中斷，重新排入核對。相同幣種的多筆持倉共用一次補查，按各自檢查點重播；仍使用 Web Locks 保證同網站只有一個負責追蹤的分頁。
- 中斷期間先碰停損再反彈者記錄停損，不會恢復為持倉。已確認 TP1 不撤銷，TP2／TP3 按相同順序繼續，原單一目標平倉結果不因較遠目標核對被重寫。費用與滑價沿用每筆原設定，跳價損失可能超過原預算。
- 公開聚合成交查詢目前限近 48 小時；接近上限會保守停止。缺失成交編號、檢查點不符或超過範圍時，僅未判定部分列待核對，排除相應勝率／觸及率分母。逾時、暫時網路錯誤與限流則保留核對中，依退避及 Retry-After 自動重試。
- 畫面新增核對中篩選與重新核對按鈕，分開列出連續追蹤平倉、補查確認平倉與待核對。重新核對會重新驗證原檢查點，不會直接解除待核對。舊版沒有成交編號的待核對紀錄維持原樣，無法自動證明中斷期間的觸價順序。
- 仍是以公開聚合成交模擬的前向績效，不等同實際帳戶成交或完整逐筆委託簿。歷史回測維持原本 4H／15M 策略流程，不使用這個恢復流程補開交易。

## 瀏覽器本機歷史回測與掃描紀錄

「策略回測」可選擇台北日期、固定合約、資金、手續費及滑價，最多 90 天。歷史 K 線、報告與完整掃描快照保存在目前網站的 IndexedDB；原有前向模擬繼續使用原 localStorage 紀錄，不會被回測覆寫。沒有後端、雲端同步或真實下單，手機與電腦各自保存。清除網站資料或更換網站來源，不能自動讀取原紀錄。

- 原策略僅使用已收盤 4H／15M，先載入 4 天暖機資料，以每個決策時間當時可見的 K 線計算，透過 Web Worker 重播。下一根 15M 開盤加不利滑價作為模擬成交，不回填訊號收盤價。
- 預設沿用訊號停損與固定止盈，成交後價差不足 2R 會略過並顯示原因。因此原先恰好 2R 的訊號在加入滑價後可能大量略過。另可明確選擇「依模擬成交價重算至少 2R」研究變體；此設定只影響該次回測，不改動即時策略或前向模擬。
- 每筆獨立使用參考資金的 3% 風險，將預估停損滑價與進出手續費計入數量，遵守合約數量／價格精度。跳空可能超過預算；未模擬共用保證金、資金費率、委託簿深度或複利帳戶。
- 同一根 K 同時觸及停損、止盈時，預設停損優先，也可標記不確定並排除勝率。跳空用開盤價處理。期末仍持倉者不強制平倉、不列入已實現績效，歷史 OHLC 不能判定精確盤中成交順序。
- 報告包含費後勝率、淨損益、最大回撤、獲利因子、最大連敗、按合約／月份／方向分組、交易明細，以及可切換 15M／4H 的均線與進出場圖。曲線是獨立訊號累積已實現淨損益，並非共用 70 USDT 的帳戶淨值。報告可重新載入並提供 JSON 匯出。
- 固定合約回測使用目前可取得的交易精度，會有選樣及生存者偏差；「填入目前 Top20」只是固定名單，不能代表歷史 Top20。
- 「已保存的當時 Top20」只使用該決策時間之前已完成保存且未超過 15 分鐘的排名快照，報告列出時段覆蓋率。缺失排名不推測、不改用目前 Top20。啟用新版前沒有保存的排名無法自動補回。
- 「掃描歷史」保存每輪 Top20 的成交額排名、條件成立／不成立、均線值、候選與資料錯誤；頁面可選擇過去掃描查看，不僅記錄符合策略的幣種。關閉頁面中途未完成的掃描不能保證保存，已完成批次才有完整快照。
- 行情分頁請求並快取，資料缺漏、取消、限流或本機儲存失敗會顯示原因。可取消回測；完成下載的資料可重用。頁面仍須開啟並保持網路可用，維持原有每根 15M 收盤後掃描，不會在背景排程每小時執行。

## 三段目標與觸及率

策略卡片同時顯示 TP1／TP2／TP3，分別為參考進場至停損距離的 2R／3R／4R。新前向模擬及重新執行的歷史回測，在實際模擬成交後另以成交價與原停損距離建立 2R／3R／4R 的三段觀察，依 tick 朝獲利方向取整。三段觀察與原單一目標損益統計獨立；不分批出場、不移動停損、不改寫原單一目標交易結果。

TP1 後仍追蹤較遠目標，原停損觸及後剩餘目標皆記為先停損，之後反彈不補計。每段觸及率＝該段已觸及／（已觸及＋先停損），並列出分子、分母、未結束、待核對及無效價位數。觸及率不是費後勝率，各段已判定樣本數可能不同；不能直接將觸及率相乘推算績效。歷史同根雙觸價沿用所選保守停損或不確定政策，跳空先按開盤價判斷；較早已確認的觸及不因後續停損消失。

前向模擬即使原目標已平倉，只要較遠目標仍待判定，會保持行情訂閱；新版持倉斷線、頁面重開或超過 30 秒未取得報價後，僅剩餘未判定目標進入自動核對，已觸及結果保留。舊 localStorage 紀錄保留且不回填三段結果；舊回測報告可讀取，需重新回測以取得三段資料。三段結果隨原紀錄保存在本瀏覽器，沒有後端。

## 清空模擬紀錄

「清空」位於「暫停新增」右側。使用者確認後，清空本網站／本瀏覽器的全部模擬交易、持倉與恢復檢查點；費率及暫停設定保留，歷史回測報告與掃描歷史不受影響。清空時間會隨新空帳本一起保存，清空前已確認的策略訊號不會在同輪掃描或重新整理後立即重建。儲存失敗時保留原帳本，不停止原追蹤。清空後繼續等待之後新產生的訊號。

## 隱藏 RSI＋爆量掃描

每次原策略掃描啟動時，獨立背景檢查所有目前 TRADING 的 Binance USDT 永續合約。連點頁首 CODEX BOT 5 次（相鄰點擊不超過 1.2 秒），或進入 site/index.html#rsi-volume，開啟隱藏面板；「隱藏」返回策略掃描。隱藏入口並非權限控管。

條件：同一根最新已收盤 15M 的 RSI(14) < 30，且基礎資產成交量 ≥ 前根的 3 倍（增加 200%）。前根零量沒有有限增幅，略過。RSI 為 Wilder 平滑，前 14 個變動 SMA 起始，再遞迴更新，最多使用 250 根已收盤 K 線。各合約以同一輪 Binance 時間固定收盤快照；不使用尚未收盤 K 線。資料錯誤／取消／限流顯示不完整，不假稱掃完；同根更新重用已驗證結果，下根重新抓取。

此名單不改變原策略、模擬持倉與績效；手動更新及取消只影響 RSI 掃描。沒有自動下單。切換頁籤繼續掃描，關閉網站停止。公開資料端點與成交量欄位見 [Binance 官方文件](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/rest-api/market-data)。
