# Codex Bot Bryce — Binance 策略掃描

頁面在原本「全部訊號」的位置提供「策略掃描」。舊市場雷達、五因子評分引擎、設定與測試已移除。新版策略掃描使用 `strategy-engine.js`、`strategy-data.js` 與 `strategy-scanner.js`；模擬交易另外載入 `price-feed.js`、`paper-engine.js` 與 `paper-panel.js`。不會啟動舊訂單流程或寫入後端訂單。

## 本版策略

僅使用幣安已收盤的 **4H 與 15M** K 線，不抓取或混用其他週期。MA 為收盤價的簡單移動平均（SMA），不是 EMA。

| 判定 | 做多 | 做空 |
| --- | --- | --- |
| 4H 方向 | 收盤價 > MA20，且本根 MA20 > 前一根 MA20 | 收盤價 < MA20，且本根 MA20 < 前一根 MA20 |
| 15M 回踩／反彈 | 確認 K 或緊鄰前一根 K 的高低區間觸及該根 MA10 或 MA20 | 相同觸及條件 |
| 15M 收盤確認 | 前一根收盤 ≤ 當時 MA5，確認 K 收盤 > 當時 MA5 | 前一根收盤 ≥ 當時 MA5，確認 K 收盤 < 當時 MA5 |

條件必須全部成立才顯示候選。依使用者最新指示，本版暫不使用 HH／HL、LH／LL 結構或成交量條件；不以舊雷達分數排序。候選依合約名稱排列。

## 資金與風險

- 初始總資金：**70 USDT**，可在頁面調整並儲存在瀏覽器本機。
- 單筆風險預算：總資金 × **3%**，70 USDT 對應 **2.10 USDT**。
- 進場參考：15M 確認 K 收盤價。
- 停損：若前一根 K 觸及 MA10／20，使用該根與確認 K 的區間極值；只有確認 K 觸及時則使用確認 K 極值。做多放在最低點下方 1 tick，做空放在最高點上方 1 tick。
- 目標：依進場至停損的距離計算 **至少 2R**，並朝有利方向對齊 tick 精度。
- 部位數量：風險預算 ÷ 停損距離，再依幣安 LOT_SIZE 向下取整並遵守最大數量。估算價格風險不超過預算；部位不足最小數量或名目金額時顯示原因。

3% 指單筆的資金風險，不是固定停損價差。風險／獲利是價格差估算，未含手續費、滑價與資金費率，也不保證實際成交損失上限。名目部位可能高於總資金，保證金需求依實際槓桿而定。多筆候選各自計算 3%，沒有執行交易或自動分配多筆保證金。

## 資料、更新與畫面

- 透過 `https://fapi.binance.com/fapi/v1/exchangeInfo` 篩選交易中的 USDT 永續合約；每輪重新讀取 `/fapi/v1/ticker/24hr`，依官方 `quoteVolume`（24 小時 USDT 成交額）由高到低選取前 20 個，只有這些合約會進入策略掃描。有效資料少於 20 個時只掃描實際可用數量；排名資料失敗時回報錯誤，不改掃全市場。
- 使用 `/fapi/v1/time` 與 `/fapi/v1/klines` 對齊幣安時間。只允許 `4h`、`15m`，每次讀取 80 根。
- 先檢查 4H 趨勢，成立後才抓該合約 15M。前 20 名合約初次掃描需要一段時間，畫面顯示即時進度與已符合條件的候選。
- 全域請求間隔 250ms、最多 3 個工作並行；遇到 429／418 依 Retry-After 暫停；單一合約資料錯誤會跳過並顯示計數。
- 各週期資料快取至該週期下一個收盤邊界。每根 15M 收盤後自動重新掃描；舊候選到期即移除，且排除未收盤、缺漏、重複或過期 K 線。
- 卡片顯示多空方向、進場參考、停損、目標、估算風險、目標獲利與部位數量；可展開查看均線及確認時間。
- 掃描使用幣安原生合約名稱與單位，例如 `1000PEPEUSDT` 保留千顆合約單位，數量、tick 與停損風險使用同一單位。

## 使用

將 `site/` 作為靜態網站根目錄，或透過儲存庫根目錄 `index.html` 導向 `site/`。新版掃描頁不需要 `/api/orders` 後端或 API Key。舊版訂單／推播的資產保留在儲存庫，但掃描頁不會載入它們。公開價格模組會供模擬交易追蹤使用。

策略卡片仍是待執行候選，並由下方獨立的前向模擬面板累積結果。**沒有真實自動下單或歷史回測功能**；上方總資金不會因模擬盈虧自行變動。

## 前向模擬交易（第一版）

策略掃描下方新增「模擬交易」。此功能從啟用後開始累積結果，不是歷史 K 線回測，也不會向幣安送出真實交易。

- 新候選以 `幣種＋方向＋15M 確認時間` 去重，同一訊號只記錄一次；候選依照其產生後的新成交報價模擬進場，沒有回填已過去的確認 K 收盤價。
- 沿用訊號的停損、止盈；按模擬進場價檢查價差盈虧比至少 1:2。若報價已越過界線、盈虧比不足、30 秒內沒有新報價、或數量未達幣安最小要求，就記錄「略過」與原因。
- 70 USDT 為預設單筆參考總資金，每筆風險預算 3%；數量依新成交價重算，將估算進出場手續費與停損滑價納入預算。因此部位可能與策略卡片的未含費用參考數量不同。
- 預設單邊手續費 0.05%、單邊不利滑價 0.02%，都是可調整的模擬假設，不代表實際帳戶費率。每筆訊號會固定當時資金、費率與滑價，調整只影響後續新紀錄。
- 透過公開行情 WebSocket 接收成交報價，逐次檢查停損／止盈觸價；模擬市價出場使用觸發時報價加不利滑價。行情跳價可能導致損失超過原先預算，費後盈虧比也可能低於 2R。未計資金費率與委託簿深度。
- 已進場的紀錄不因候選到期或下一輪不再符合策略而消失；「暫停新增」仍會繼續追蹤原有持倉。
- 每筆訊號獨立模擬，可以同時記錄不同訊號；沒有共用保證金、槓桿限制或帳戶淨值資金曲線。累計盈虧與回撤都是獨立訊號結果的合計。
- 勝率以淨損益大於 0 的已平倉筆數，除以所有已平倉筆數。未平倉、略過與待核對不列入分母。另顯示多空勝率、平均淨損益、最大連敗與累積淨損益回撤。
- 重新開啟頁面、網路斷線、行情連線重建或連續超過 30 秒未取得成交報價時，未結束持倉會標為「待核對」，不推測離線期間的觸價順序，也不計入勝率。這會影響樣本完整性，應同時查看待核對數量。
- 紀錄保存在目前網站／瀏覽器的 localStorage，支援 JSON 匯出。清除網站資料、更換瀏覽器或更換網址不會自動沿用紀錄。
- 使用 Web Locks 確保同一網站同時只有一個分頁負責追蹤，其他分頁唯讀。需使用支援 Web Locks 的 HTTPS 或 localhost 環境。

第一版需要保持頁面與網路可用。若要在關閉瀏覽器後繼續追蹤，需再增加常駐後端與資料庫。

## 驗證

使用 Node.js 24：

```powershell
node --test tests/*.test.cjs
```

測試涵蓋獨立週期、MA 方向、回踩與穿越、收盤 K 線驗證、停損與 2R、3% 風險與交易精度、請求快取、限流與取消。`tests/strategy-fixtures.cjs` 是測試資料，正式頁面不會載入。

模擬交易測試另涵蓋訊號去重、後續報價成交、手續費與滑價、觸價出場、追蹤中斷、費後勝率、設定快照與資料保存格式。瀏覽器驗證使用隔離的測試行情，測試數字不代表策略真實勝率。匯出下載的瀏覽器驗證因下載授權被拒絕而未完成。
